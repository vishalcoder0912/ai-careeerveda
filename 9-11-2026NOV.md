1. Folder Location
Create it inside the backend so it's not exposed directly to the browser:
backend/
└── uploads/
    └── brochures/
        ├── pg-gen-ai-agentic-ai-brochure.pdf
        ├── pg-data-science-brochure.pdf
        └── pg-marketing-brochure.pdf
Why here: Files in backend/uploads/brochures/ are not web-accessible by default. Your backend will read them and stream them to the user only when they click download. This keeps you in control of permissions and rate-limiting.
Alternative: If you already use ImageKit (which your project does), you can keep the binaries in an ImageKit folder /careerveda/brochures/ and store just the URL in MongoDB. But if you want a local folder, use the path above.

3. How It Connects to Your Program Records
Your Program model already has a brochureUrl field. You have two options:
Option A — Local file path (if using the folder):

Option B — ImageKit URL (if staying with your existing CDN):

The backend download route will look up the program by slug, read brochureUrl, and stream that exact file to the user with:
- Content-Disposition: attachment; filename="gen-ai-agentic-ai-brochure.pdf"
So clicking "Download Brochure" on the Gen AI program always downloads gen-ai-agentic-ai-brochure.pdf, clicking on Data Science downloads data-science-brochure.pdf, etc.
